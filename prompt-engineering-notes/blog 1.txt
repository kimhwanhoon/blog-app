# 멀티 유저 블로그 플랫폼 구축 계획

## Context

`/Users/kimhwanhoon/Desktop/blog` 는 현재 빈 디렉토리. velog/Medium 스타일의 **멀티 유저 SaaS형 블로그 플랫폼**을 그린필드로 구축한다.

핵심 요구사항:
- 누구나 가입해서 자신의 블로그(글/태그/팔로워)를 운영
- URL은 경로 기반: `/@username/post-slug`
- 풍부한 에디팅 경험 (Plate.js 블록 에디터)
- 태그/카테고리, 댓글, 좋아요/북마크, 팔로우/피드까지 MVP에 포함
- 다크모드 지원 (next-themes)

## Stack (최신 안정 버전)

| 분류 | 선택 | 비고 |
|---|---|---|
| 프레임워크 | **Next.js 15** (App Router, RSC) | React 19 기반 |
| 패키지 매니저 / 런타임 | **bun** | 설치/스크립트 실행 |
| DB | **Neon** (serverless Postgres) | `@neondatabase/serverless` 드라이버 |
| ORM | **Drizzle** | `drizzle-orm` + `drizzle-kit` (push/migrate) |
| UI | **shadcn/ui** + Tailwind v4 | `bunx shadcn@latest init` |
| 인증 | **Better Auth** | Drizzle adapter, 이메일+OAuth(Google/GitHub) |
| 에디터 | **Plate.js** | 블록 단위 에디터, JSON 저장 → 서버에서 HTML 직렬화 |
| 미디어 | **Cloudflare R2** (S3 API) | presigned PUT URL로 클라이언트 직업로드 |
| 테마 | `next-themes` | shadcn 기본 토큰 |
| 배포 | **Vercel** | Edge가 아닌 Node 런타임 (Drizzle 호환) |
| 검증 | **Zod** + `react-hook-form` | 폼 / 서버 액션 입력 검증 |

## 데이터 모델 (Drizzle 스키마 핵심)

`db/schema/blog.ts`
- `post`: id, authorId, title, slug, excerpt, contentJson (Plate), contentHtml, coverImageUrl, status (`draft|published`), publishedAt, viewCount, createdAt, updatedAt
  - unique index `(authorId, slug)`
- `tag`: id, name (unique), slug
- `postTag`: composite PK `(postId, tagId)`
- `comment`: id, postId, authorId, parentId(self ref, 1단계 답글), body, createdAt
- `reaction`: `(postId, userId)` PK, type (`like`)
- `bookmark`: `(postId, userId)` PK
- `follow`: `(followerId, followingId)` PK, createdAt

`db/schema/auth.ts` 는 Better Auth가 요구하는 user/session/account/verification 테이블. `user`에 `username` (unique), `displayName`, `avatarUrl`, `bio` 컬럼 추가.

## 단계별 구현 순서

1. **프로젝트 초기화**
   - `bun create next-app@latest .` (App Router, TS, Tailwind, src 디렉토리 미사용)
   - `bunx shadcn@latest init` → button, input, dropdown-menu, dialog, avatar, badge, textarea, sonner 설치
   - `next-themes` 추가, `app/layout.tsx`에 `ThemeProvider`

2. **DB / Drizzle 셋업**
   - Neon 프로젝트 생성, `DATABASE_URL` 을 `.env.local`에 추가
   - `db/client.ts`에서 `drizzle(neon(...))` 구성
   - `db/schema/*` 작성 → `bunx drizzle-kit push` 로 첫 스키마 적용
   - `package.json`에 `db:push`, `db:studio` 스크립트

3. **Better Auth 설정**
   - `lib/auth.ts`: `betterAuth({ database: drizzleAdapter(db, { provider: 'pg' }), emailAndPassword: { enabled: true }, socialProviders: { google, github } })`
   - `app/api/auth/[...all]/route.ts` 핸들러 마운트
   - `lib/auth-client.ts`로 클라이언트 훅 노출
   - `middleware.ts`에서 `(app)` 그룹 보호

4. **사용자 프로필 / username**
   - 가입 직후 `username` 미설정이면 `/onboarding`으로 리다이렉트
   - username 검증: 소문자/숫자/`_`, 3-20자, 예약어 차단(`me`, `admin`, `api` 등)

5. **에디터**
   - `components/editor/plate-editor.tsx`에 Plate 코어 + 기본 플러그인(heading, list, blockquote, code-block, link, image, mention)
   - 이미지 삽입은 R2 presigned URL 흐름:
     1. 클라이언트가 `POST /api/upload`로 contentType/size 전달
     2. 서버가 `getSignedUrl(PutObjectCommand)` 반환
     3. 클라이언트가 R2에 직접 PUT, 성공 후 공개 URL을 에디터에 삽입
   - 저장 시 서버 액션으로 `contentJson` + `contentHtml`(직렬화) 같이 저장

6. **글 라우팅 / 렌더링**
   - `app/@[username]/page.tsx`: 해당 유저 published 글 목록 + 프로필 헤더
   - `app/@[username]/[slug]/page.tsx`: 글 상세, `generateStaticParams` 없이 `revalidate`
   - 댓글, 좋아요, 북마크 버튼은 클라이언트 컴포넌트 + 서버 액션
   - 태그 페이지: `app/@[username]/tag/[tag]/page.tsx`

7. **피드**
   - `/feed`: 로그인 사용자가 팔로우한 사람들의 최신 글 (페이지네이션 cursor)
   - `db/queries/feed.ts`에 `getFeed(userId, cursor)` 작성

8. **상호작용 (서버 액션)**
   - `actions/posts.ts` (createPost, updatePost, publishPost, deletePost)
   - `actions/social.ts` (toggleFollow, toggleLike, toggleBookmark, addComment, deleteComment)
   - 모든 액션 입력은 Zod로 검증, 인증 체크는 공통 헬퍼 `requireUser()`

9. **다크모드 / 테마 토글**
   - `components/shared/theme-toggle.tsx`로 next-themes 토글
   - shadcn 기본 토큰만 사용 (커스텀 테마는 후속)

10. **배포**
    - Vercel 프로젝트 연결, env vars 등록 (DATABASE_URL, BETTER_AUTH_SECRET, BETTER_AUTH_URL, R2_*, OAuth keys)
    - `vercel.json` 불필요 (Next 15 기본 설정), `runtime = 'nodejs'` 명시 (Edge 회피)
    - Bun 빌드 활성화: Vercel 프로젝트 설정에서 Install Command를 `bun install`로

## 주요 결정/주의 사항

- **Plate.js JSON + HTML 이중 저장**: 편집은 JSON으로, 공개 페이지 SSR은 HTML로 → 클라이언트 번들에 Plate 미포함, SEO/속도 모두 잡음.
- **`@username` 라우팅**: Next.js의 그룹 라우트(`(...)`)와 충돌하지 않도록 `app/@[username]/...` 디렉토리는 *parallel route* 처럼 보일 수 있으나, `@`는 디렉토리명에 안전하지 않다. 실제로는 `app/[username]/...` 폴더에 두고 URL만 `/@user`로 받도록 `middleware.ts`에서 prefix 제거 + slug 매칭으로 처리한다.
  - 대안: `app/(public)/[username]/...` 폴더를 두고 `next.config.ts`의 `rewrites`에서 `/@:username/:slug*` → `/:username/:slug*` 로 매핑.
  - **권장: rewrites 방식** (middleware보다 단순, 캐시 친화적).
- **R2 CORS**: bucket에 PUT 허용 origin 등록 필요.
- **Drizzle 마이그레이션 전략**: 초기엔 `drizzle-kit push`로 빠르게 반복, 프로덕션 직전부터 `generate` + `migrate`로 전환.
- **Edge runtime 금지**: Better Auth + Drizzle + Neon HTTP 드라이버 조합은 node 런타임이 가장 안정적.

## 검증 방법

각 단계 완료 후 다음으로 end-to-end 확인:
1. `bun run dev` 실행 → `http://localhost:3000`에서 가입/로그인 흐름 확인
2. 대시보드 → 새 글 작성 → 이미지 업로드(R2 PUT 성공) → 발행 → `/@me/slug`에서 보이는지
3. 다른 계정으로 로그인 → 팔로우/좋아요/북마크/댓글 확인 → `/feed`에 반영
4. `bunx drizzle-kit studio` 로 DB row 확인
5. `next build` 성공 + `next start`로 프로덕션 모드 스모크 테스트
6. 라이트/다크 토글, 모바일 반응형 확인
